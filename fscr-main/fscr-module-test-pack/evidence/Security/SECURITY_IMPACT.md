1. **Safe to run first:** none is impact-free, but **task 1 (audit)** is the smallest and reversible (turn OFF again); it needs only your OK, no new access. Tasks 3 and 4 with a `GAPFILL_` connector and **no credentials** are next safest, once `rmc_scope` exists.
2. **Need your approval:** task 1 (environment-wide audit), task 2 (publishes **104** SoD/sensitive/transaction algorithms; treat as one-way), task 5 (names real owners), task 6 (changes users' roles).
3. **Cannot run yet:** tasks 2, 5, 6 need the **Risk Administrator** role on our test user; tasks 3, 4 need the **Risk Cloud scope** (`rmc_scope`) on the sign-in app.

## Oracle docs (pages opened 2026-11-24; what Oracle itself says)
- **Audit (task 1):** auditing can be stopped by setting the audit level back to None; no fixed retention for audit data ([audit-policies](https://docs.oracle.com/en/cloud/saas/human-resources/faucf/audit-policies.html)). Only users with View Audit History see audit reports ([run-audit-reports](https://docs.oracle.com/en/cloud/saas/risk-management-and-compliance/26b/farrm/run-audit-reports.html)). Setup steps: [set-up-auditing](https://docs.oracle.com/en/cloud/saas/risk-management-and-compliance/26b/farrm/set-up-auditing.html). Oracle states **no performance impact figure**.
- **Algorithms (task 2):** Oracle has **no docs.oracle.com page** for publish/draft or unpublishing of Redwood algorithms. Closest (Classic controls): a control must be made inactive before deletion, and deleting it deletes its results ([delete-an-advanced-control](https://docs.oracle.com/en/cloud/saas/risk-management-and-compliance/26b/faacm/delete-an-advanced-control.html)).
- **Data sources (tasks 3, 4):** an EPM data source connects Risk to EPM-ARCS/FCCS and runs sync jobs that pull access and transaction data ([set-up-epm-data-sources](https://docs.oracle.com/en/cloud/saas/risk-management-and-compliance/26b/farrm/set-up-epm-data-sources.html), [overview-of-data-sources](https://docs.oracle.com/en/cloud/saas/risk-management-and-compliance/26b/farrm/overview-of-data-sources.html)). A data source can be edited or **deactivated** (clear Active) and reactivated; the EPM host cannot be changed; deactivating needs dependent models removed first; **no delete is documented** ([maintain-synchronized-data-sources](https://docs.oracle.com/en/cloud/saas/risk-management-and-compliance/26b/farrm/maintain-synchronized-data-sources.html)).
- **Process owners (task 5):** Oracle has **no page** on "default process owner". Closest: worklists for incident controls go to the result investigators chosen at deploy ([select-worklist-recipients](https://docs.oracle.com/en/cloud/saas/risk-management-and-compliance/26b/faacm/select-worklist-recipients.html)). So "owners receive incidents" is our reading, **not confirmed by Oracle**.
- **Roles (task 6):** Risk Power User can create, edit and run controls, run and schedule analysis, and manage algorithms; Risk Administrator inherits it ([Risk_Administrator_job_roles](https://docs.oracle.com/en/cloud/saas/risk-management-and-compliance/26b/farsr/Risk_Administrator_job_roles.html)). So the **8 Risk Administrator holders already have Power User access** through inheritance. A role request can be withdrawn role by role ([make-a-role-request](https://docs.oracle.com/en/cloud/saas/risk-management-and-compliance/26b/faacm/make-a-role-request.html)); granted roles can be removed by an approver with Remove Access ([remove-roles](https://docs.oracle.com/en/cloud/saas/risk-management-and-compliance/26b/faacm/remove-roles.html)).
