How the gaps in FSCR are filled and checked

FSCR has skills for – of – ERP and SCM tasks. This page shows how each of the other – is handled, and where each one stands today.

Step by step

How one gap is filled

The same six steps for every task. Read only on existing data; only new test records are added.

  2. 1

    Read-only export

    Export what Oracle holds for the task, read only, to learn the exact shape of the data.

  3. 2

    Write a generic skill

    Write the skill in the same shape as FSCR's own skills. Generic: no customer data, usable for any customer.

  4. 3

    Load one new test recordCSV or REST

    Load one brand-new test record through the task's CSV package or REST route.

  5. 4

    Read it back

    Read the record back from Oracle and compare it with what was sent.

  6. 5

    Fresh Claude test

    A fresh Claude, given only the skill, does the task again with its own new record. Any wrong sentence is fixed and tested again.

  7. 6

    Status card and evidence

    The result goes on a status card for the task, with the read-backs and screenshots as evidence.

Outcomes

Where a gap ends up

Each gap that has been worked on ends in one of four places. The counts are the same as on the dashboard.

Tested
–

Loaded into Oracle, read back, and passed a fresh test.

Written
–

Skill written; live test pending, because the load cannot be put back or needs credentials.

Some need outside input, such as a partner account or provider credentials.
Failed
–

A proven cause, written down with a next step.

Some need outside input, such as a missing permission or a job name Oracle does not publish.
Screen-only
–

No CSV or REST route; only the Oracle screen can do it.

Needs outside input: a consultant unlocks it

For some written and failed tasks the skill is ready, but we cannot finish the test on our own. One thing is missing that only a consultant or the owner of the Oracle environment can give, for example:

  • a permission on the test environment
  • the exact name of an Oracle background job that Oracle does not publish
  • a test account with a tax partner
  1. We write down what is missingOne clear ask per task, on its status card.
  2. A consultant provides itGrants the access, reads the job name once on the Oracle screen, or sets up the partner test account.
  3. We run the normal test againLoad, read back, fresh check. If it passes, the task moves to Tested.

No count is shown: the task files describe this in words, not as a separate status we can count.

– tasks are still open: not started yet.

In plain words

Easy, harder, and needs help

Not every task is the same amount of work.

Loads straight away

Oracle offers a CSV package or a REST route. The skill loads one test record and reads it back.

Needs prerequisites first

The record hangs off something else, such as a test legal entity or business unit. That is built first, as a test record of its own.

Screen only

No CSV and no REST route. A person does it on the Oracle screen; the proof is kept on the task's card.

Needs someone to provide something

A consultant or the environment owner has to give a permission, a name or an account before the test can run.

Definitions

What the words mean

Tested

Loaded into Oracle and checked by a fresh Claude.

Written

Skill written, live test pending.

Skills available = skills FSCR already had + tested + written. Security is left out of every count: it has no missing tasks.
