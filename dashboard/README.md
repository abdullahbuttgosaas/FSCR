# FSCR gap filling dashboard (ERP and SCM)

1. **Update:** run `python dashboard\update.py` from the work folder (standard library, no arguments, no network), then deploy with `vercel --prod --yes` in this folder; full steps in `UPDATE_STEPS.md`. Live site: https://fscr-gap-dashboard.vercel.app (also `/story.html` and `/technical.html`). Only `index.html`, `story.html`, `technical.html`, `assets\` and `data\` are served (see `.vercelignore`). One update refreshes all three pages.
2. **Where numbers come from:** total per module = `Total Tasks` in `fscr-main\_fscr_all_module_counts\module_totals.csv` (FSCR catalog count); missing tasks and their status = rows of `gaps-filled\gap_index.csv`; the 19 owned module names and order = `gaps-filled\gap_progress.tsv`; `MODULE_TRACKER.csv` and `MODULE_RESULT.md` per module are cross-checks only.
3. **Definitions:** total = all catalog tasks; supported_before = total minus the module's rows in `gap_index.csv`; tested = status tested; written = status written (old tracker word "skipped-unsafe" counts as written); skills_available = supported_before + tested + written; screen-only, failed, open as in the index.
4. **Left out:** Security has no gap rows, so it is in no chart and in no headline number (its 6 tasks all had skills before). All 18 other totals were found; no module shows "total not found".
5. **Checks done (2026-11-25):** for every module before + tested + written + screen-only + failed + open = total, and missing equals the catalog's own `Missing (b+c)`; 935 index rows = 935 missing; Common Features 58 tested / 14 written and Procurement 14 / 4 match their trackers and `MODULE_RESULT.md`; `update.py` prints any mismatch on its last line and exits with code 1.

**Decisions:** headline sums 18 modules (Security out); bars use one shared scale (bar length = module total) so big and small modules compare fairly; tested 74 is one more than the 73 in `CONTEXT.md` because Manage FOB Lookup was tested in Procurement sitting 3; `history.json` starts today (no past snapshots were made up); the page reads `data\data.json` + `history.json` when hosted and `data\data.js` when opened by double-click (browsers block fetch on file pages).

## Three pages (added 2026-11-27)

- **`index.html`** (Dashboard): same numbers and behaviour as before, now in the shared themes (gradient title and numbers, glass cards, moving background), with the top bar (Dashboard, How it works, Technical details, theme picker) and a "See how it works" button next to the title.
- **`story.html`** (How it works, rebuilt 2026-11-27 after feedback: no scrolling): a dark, colourful slideshow that plays by itself (6.5 to 13 seconds a slide, progress bar at the bottom) with play/pause, back/next, arrow keys, swipe, and `#1` to `#6` in the address to open one slide. Moving background light and floating dust; each slide animates every time it shows: title letters rise, rings draw and numbers count up, particles flow from the three sources into the GoSaaS hub, the four loop steps light up in turn. Slides: title; FSCR today (skills before); the gaps (missing tasks); GoSaaS fills the gaps; FSCR after (one ring: had a skill + added by GoSaaS, counting to skills available now, with the gain); what is left (open tasks only) with buttons to technical details and the dashboard.
- **`technical.html`** (Technical details): the six steps for one gap; where a gap ends up (tested, written, failed, screen-only cards, plus "needs outside input": what a consultant has to provide and the three steps to unlock it); easy, harder and needs help; a per-module table with inline bars and a total row; the definitions.
- **Shared files:** `assets\site.css` (the three themes as colour tokens, the moving background, the top bar and theme picker) and `assets\site.js` (theme picker, moving background, data loading, count-up, reveal on scroll). Plain HTML, CSS, JavaScript and inline SVG: no CDN, no build step, about 95 KB for all three pages and the shared files.
- **Check:** `python dashboard\check_pages.py dashboard dashboard\screenshots` (Playwright) opens all three pages at 1440 and 390 px wide, saves one screenshot per slide and section in `screenshots\` (plus every page in every theme, and the open theme picker), and checks: each theme sets the right background on every page and keeps sideways scroll off; the picker works by mouse and keyboard and the choice carries to the next page; the story moves on by itself; no slide is cut off; the story no longer mentions written, failed or screen-only; every number on the story and technical pages equals `data.json`; the module rows sum to the totals; no sideways page scroll; every link is relative and works; the nav and buttons land on the right page; reduced motion shows final numbers at once; no console errors. Pass the live address instead of `dashboard` to check the hosted pages. It is kept off the live site.

**Decisions for the three pages:**
- **Same data, no new fields.** Both new pages read the same file as the dashboard (`data.json` hosted, `data.js` by double-click) and use only fields `update.py` already writes (`summary`, `modules`, `left_out`, `updated`), so `update.py` and its history logic are unchanged. Security stays out because it uses the same `in_charts` flag as the dashboard.
- **"Needs outside input" has no number.** Neither `gap_index.csv` nor the `STATUS.md` cards have a field that marks a task as waiting for outside input; the reason is only in free text. Counting it from words would be a guess, so the page shows the group (inside written and failed) with examples and no count.
- **The gaps** = missing tasks (`summary.missing`, 935 today); **what is left** on the story = open tasks only (asked for: no failed or screen-only on that page). **FSCR after** shows one gain segment, "Added by GoSaaS" = tested + written, so the ring still ends at skills available now; the written split and the "N tested, N written" line were removed from the story as asked (the split is on the technical page).
- **Ring scale** = all tasks (`summary.total`), same as the dashboard ring, so the story's percentages match the dashboard.
- **Table bars** use one shared scale (bar length = missing tasks), like the dashboard bars; a module with 0 open is never called complete.
- **Themes:** three, for all three pages: **Night** (default: deep navy with blue, violet and green light), **Dusk** (deep plum with pink, orange and violet) and **Light** (the original calm look with soft pastel light). Pick one with the button at the right of the top bar; the choice is kept in this browser (localStorage `fscr-theme`) and follows you to the other pages. Each page sets the theme in its `<head>` before drawing, so there is no flash. Data colours keep their meaning in every theme (blue = had a skill, green = tested or added, amber = written, red = failed, grey = screen-only).
- **Speed (2026-11-27, after "the site became slower"):** the look stays the same, but the heavy effects are gone: no `filter: blur`, no `backdrop-filter` and no SVG drop-shadow over moving content (soft glows are now plain gradients, cards are a little less see-through), animations move only position and opacity on their own layers, and the floating dust redraws 30 times a second with at most 48 dots. Measured with `python dashboard\perf_check.py dashboard` (Chromium, 1440 px): before 7 to 15 frames a second with 27 to 61 slow frames per 4 s; after 60 frames a second on every page in Night and Light, 0 slow frames. Rule for later changes: do not add blur, backdrop-filter or SVG filters over animated parts. `perf_check.py` is kept off the live site.
- **Motion** respects `prefers-reduced-motion` (no animation, final numbers at once). Without JavaScript the text still shows.
- **No names of people**: the story names the company only.
